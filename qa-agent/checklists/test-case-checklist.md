# Test Case Checklist

Use this checklist to validate each generated `{{us-id}}.md`.

## Traceability & Coverage

- [ ] Each test case maps to at least one **acceptance criteria**.
- [ ] All acceptance criteria have **>= 1 test case**.
- [ ] Dependencies and related stories are noted.

## Quality

- [ ] Preconditions are clear and sufficient.
- [ ] Steps are unambiguous and reproducible.
- [ ] Expected results are observable and measurable.
- [ ] Test data is specified where needed.

## Scenario mix

- [ ] Happy path covered (P0).
- [ ] Negative/validation scenarios covered.
- [ ] Boundary/edge cases covered where inputs exist.
- [ ] UX messaging/disabled states covered where relevant.
- [ ] Accessibility considerations included where relevant.

## Format

- [ ] IDs follow `<US-ID>-TC-###`.
- [ ] Priorities are assigned (P0/P1/P2).
- [ ] Types are assigned (Functional/Negative/Boundary/etc.).
